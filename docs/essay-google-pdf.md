# 作文图片、PDF 与 Gemini

学生端：`/xie/zuowen-pigai/`；教师发码与管理：`/xie/zuowen-pigai/teacher`。

## 上传

可在登录前选择并预览文件；开始识别仍须通过原访问码认证。支持 JPG、PNG、WebP 与 PDF 混合追加，每篇最多 6 页，PDF 按展开后的实际页数计算。图片每张不超过 25 MiB，PDF 每份不超过 50 MiB。超页数、损坏或加密的 PDF 明确报错，不会只取前几页；本次选择失败时原有页面不变。

PDF.js 6.4.299 legacy 版本及字体、CMap、WASM 解码器均在本站提供。PDF 在设备上逐页转为最长边 2400 像素的 JPEG，点击识别后才提交这些页面。扫描 PDF 无需文本层。可转正、排序、删除页面；圈注和导出的报告使用同一张转换后的图片。

## 只使用 Gemini

从 2026-10-19.2 起，手写识别、逐段语言复核、评分、评语全部调用 Gemini。运行时代码不再读取智谱、DeepSeek 或 Google Cloud Vision 的密钥，不会回退到这些服务。历史批改记录保留。

唯一必填密钥：`GEMINI_API_KEY`。配置步骤：

1. 在 Google AI Studio 创建可用的 Gemini API key。
2. 打开 Supabase 项目，进入 Edge Functions → Secrets。
3. 新增名称 `GEMINI_API_KEY`，将 key 填入 Value，保存。
4. 刷新作文页面，查看 Gemini 配置状态。

`GEMINI_MODEL` 为选填，默认 `gemini-3.8-flash`。所有步骤使用同一个模型设置。

密钥只保存在服务器。未配置时允许本地文件预览与访问码管理，但不创建批改或发起付费 AI 请求。健康检查报告配置状态，不代表已经成功调用 AI。

## 原字与圈注

识字提示词要求保留学生原有错别字和病句，不自动纠正；明确划掉的文字不抄录，难辨字使用 □，不确定行在核对页面提示。仍需教师对照原图确认，不能把模型自报的完整识别视为准确率证明。

Gemini 按行返回估计框，坐标顺序为 [ymin,xmin,ymax,xmax]，归一化至 0–1000。服务器检查范围、方向和有限数值，转为现有叠加坐标格式。所有 Gemini 位置均为待核对区域，不能升级为精确单字定位；无效框保留文字和批注清单。人工改动该页识别文字后，旧坐标失效。

批改保留原有 17 套评分规则、逐段复核、访问码认证和完成后扣次机制；□ 不作为学生错别字扣分。历史专用 OCR 字框可以继续显示，但不会据此标称新 Gemini 结果为字级定位。

### 2026-10-19.3 接口修复与真实调用

修复 `generateContent` 输出格式参数：`responseFormat.text.mimeType` 要使用枚举 `APPLICATION_JSON`，图片的 `inlineData.mimeType` 则仍是 MIME 字符串 `image/jpeg`。此前误把两者都写成 MIME 字符串，文字探针实际返回 HTTP 400；修改后返回 200。参照 Google [TextResponseFormat / MimeType API](https://ai.google.dev/api/generate-content#TextResponseFormat)。

真实图片调用还发现，带大数组长度约束的 OCR 生成 schema 被接口以 400 拒绝；去掉生成端的数组长度约束后请求被接受。250 行、5000 字以及四个坐标值的限制仍在服务端解析时验证，不截断正文。识字使用 LOW thinking 与 16384 输出上限，避免单页输出提前结束；评分规则未改。

使用独立临时测试码，将用户提供的三页手写照片完成 OCR → 核对 → 两段语言复核 → 评分 → 保存。最终状态 complete；单页 OCR 约 15–23 秒。测试题目按样本内容拟定，仅用于程序验证，分数不代表原考试评分。原有用户访问码、额度与有效期均未修改，测试码验证后停用。25 项本地测试通过。

这次验证证明真实调用和保存链路可用，不是准确率达标证明。抽查发现原有错字能保留，但涂改处仍有多抄、漏字和误识别。测试只对第一页做了部分人工核对，未制作全篇逐字真值；不得以批注数或模型自报 complete 宣称全部识准、圈准。使用时务必先核对识别文字，尤其是划掉的字和插入文字；人工改动的页面继续使旧坐标失效，批注清单保留。
